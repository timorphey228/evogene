# EvoGene v3: механизмы происхождения отдельно от сохранности

Новая версия содержит специальное поле `mechanism_report` и новую таблицу в `auto_app.py`.

## Что именно проверяется

- **De novo**: синтенные ДНК-участки без аннотированных CDS у двух видов, при отсутствии кодирующих совпадений и обнаруженных копий. *Не доказательство*: нужно состояние предковой ORF и поиск удалённых белковых гомологов.
- **ДНК-дупликация**: дополнительные сходные локусы на референсе исходного вида; не доказывает паралогию.
- **Ретропозиция**: поиск предполагаемой копии-родителя у исходного вида; при наличии GFF3 проверяется, что исследуемый кодирующий участок одноэкзонный, а предполагаемый родитель имеет несколько CDS-экзонов и расположен на иной хромосоме. *Не доказательство*: необходимо подтвердить белковое родство, направленность процесса, структуру сплайсинга.
- **Транспозиция/релокация**: гомология вне синтенного положения при сохранённых фланках. *Не доказательство*: могут быть перестройки и ложные сопоставления.
- **Слияние/химеризация**: неперекрывающиеся фрагменты запроса отображаются в удалённые участки у родственника. *Не доказательство*: могут быть сборочные артефакты.
- **Неизвестное происхождение**: основная доля при отсутствии убедительных специфических признаков.

**Межвидовая сохранность ДНК и CDS теперь выведена отдельно.** Она может сосуществовать с ретропозицией, дупликацией или de novo.

Проценты — нормированные эвристические веса, **не вероятности**. При отсутствии диагностических признаков отчёт должен честно вернуть 100% неопределённости. Значение 0% у гипотезы означает *отсутствие поддержки по проведённым проверкам*, но не опровержение гипотезы.

## Запуск на Mac

```bash
cd ~/Desktop/evogene
git fetch origin
git switch feature/mechanism-classifier-v3
git pull --ff-only
source .venv/bin/activate
python -m streamlit run auto_app.py
```

Приложение сначала проверяет `datasets` и `minimap2`, затем позволяет скачать геномы и GFF3. JSON автоматически сохраняется в `results/auto_ncbi/<gene>.json`. Подробности доступны в `mechanism_report`, `retrocopy_evidence` и `synteny_evidence`.

Для локальных тестов: `python -m unittest discover -s tests -v`.

## Ограничения и следующие проверки

Нынешняя реализация **не является валидированным универсальным классификатором**. Особенно важны белковый поиск BLASTP/DIAMOND, восстановление дерева генов, проверка потенциальных ретрокопий и древнего некодирующего состояния. Для Zeus (Rcd-1r) известную биологическую аннотацию нельзя подставлять как готовый результат: программа должна найти свидетельства независимо. Если она не нашла предполагаемого родителя при ДНК-поиске, ответ останется «не установлен» — это корректнее искусственного процента ретропозиции.

## Дополнение: белковый поиск родителя

Для референса исходного вида EvoGene v3 дополнительно скачивает **белковый FASTA**
(официальный NCBI Datasets CLI: `--include protein`; отдельный кеш под
`genomes/ncbi_cache/<accession>/proteins.faa`).

Алгоритм переводит входной ген в шести рамках считывания, выбирает длинные
ORF, находит белки-кандидаты по общим 4-мерам и выравнивает лучшие кандидаты
Biopython PairwiseAligner. Через `protein_id` в GFF3 извлекает структуру CDS,
ищет многоэкзонные предполагаемые родительские копии и сравнивает с одноэкзонным
CDS исследуемого гена. Если белковый поиск отсутствует или не дал кандидатов,
происхождение не объявляется de novo автоматически.

Это **не BLASTP/DIAMOND**. Гены с интронами могут иметь прерывистую ORF в
геномной последовательности. Качество протеиновой аннотации и картирования
`protein_id` влияет на результат. Направление родитель→дочерний ген не
доказано без филогении и соответствующего предкового распределения.

Старое поле `origin_support` удалено из JSON версии v3, чтобы оно не противоречило механистической классификации. Межвидовая сохранность находится в `mechanism_report.conservation`.

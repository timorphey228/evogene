# EvoGene 🧬

**Система сравнительно-геномного анализа происхождения белок-кодирующих генов**  
Химбио-хакатон «СИНТЕЗ» · ИТМО · кейс № 2 «Откуда берутся гены?»

EvoGene помогает проверить, **как мог возникнуть ген**: de novo из ранее некодирующей ДНК, путём дупликации, ретропозиции, перемещения, слияния фрагментов или другого процесса. Программа не подгоняет ответ под одну категорию, а собирает наблюдаемые свидетельства, показывает конкурирующие гипотезы и отмечает недостаточность данных.

> **Научный статус.** EvoGene — исследовательский прототип и инструмент предварительного анализа, а не валидированный классификатор. Отсутствие совпадения в BLAST/minimap2 или CDS в GFF3 **не доказывает** происхождение de novo и не доказывает утрату гена. Таблица «уверенности» показывает качественный уровень предварительных признаков, **не вероятность в процентах**. Неизмеренные показатели и нерассчитанные деревья не выдумываются.

## Что умеет система

- Принимать **один или несколько генов-кандидатов** в формате нуклеотидного FASTA.
- Предлагать исходный вид и до 20 сравнительных видов из набора **21 вида мух** (включая дополнительную внешнюю группу *Musca domestica*).
- Находить и скачивать геномные сборки через **NCBI Datasets** с сохранением идентификаторов и предупреждением о подмене версии относительно статьи.
- Картировать последовательности **minimap2**, сохранять координаты, покрытие, приблизительную идентичность и сведения об аннотации CDS.
- Проверять дополнительные геномные локусы, потенциальные паралоги, структуру CDS и экзонов, приблизительную синтению соседних участков, кандидатные ORF и операции вставки/делеции в выравнивании.
- Выполнять предварительный поиск сходства с транспозонами, **если пользователь загрузил TE-библиотеку**.
- Строить **неукоренённое дерево по обнаруженным нуклеотидным фрагментам**: MAFFT + IQ-TREE 2 (ML, UFBoot/SH-aLRT); если доступен только MAFFT — NJ с бутстрепом; без обоих инструментов — лишь явно обозначенную *исследовательскую* NJ-кластеризацию по 7-мерам без поддержки ветвей.
- Сравнивать гипотезы **de novo, дупликации, ретропозиции, перемещения/транспозиции, слияния, TE-происхождения и древнего происхождения** с аргументами и оговорками.
- Вести **журнал этапов и ошибок с временем UTC**, сохранять версии программ, использованные сборки и SHA-256 входных данных.
- Выгружать **JSON, JSONL, Newick, MSA (если рассчитано)** и ZIP-архив проекта.

Важное различие: **дерево сходства геномных фрагментов ещё не гарантирует дерево ортологичных генов**. Без достаточно надёжных гомологов дерево не строится.

## Быстрый запуск на macOS / Linux

Требуется **Python 3.11+**. Для автоматического режима также нужны сторонние программы **NCBI Datasets CLI** и **minimap2**; для биологически более содержательных деревьев рекомендуются **MAFFT** и **IQ-TREE 2**. Их необходимо установить отдельно от Python-библиотек.

```bash
git clone https://github.com/timorphey228/evogene.git
cd evogene

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m streamlit run auto_app.py
```

Обычно Streamlit открывается по адресу **http://localhost:8501**.

**Если в приглашении терминала уже написано `(.venv)`, окружение может быть активировано.** Проверьте `which python` и `echo $VIRTUAL_ENV`; не нужно повторно активировать `.venv` в другой папке.

Для обновления:

```bash
git switch main
git pull origin main
python -m streamlit run auto_app.py
```

Проверка доступности внешних программ выполняется интерфейсом. Без `datasets` и `minimap2` автоматическая загрузка/сопоставление геномов не запускается.

## Установка NCBI Datasets CLI и minimap2 на новом компьютере

Если в EvoGene написано `datasets: не найден` или `minimap2: не найден`, кнопка **«Запустить исследование»** будет недоступна. Это **не ошибка FASTA**: приложению нужны две отдельные программы, которые **не устанавливаются** командой `pip install -r requirements.txt`.

- **`datasets`** — получает референсные геномы и аннотации из NCBI.
- **`minimap2`** — сопоставляет ген-кандидат с референсными геномами.

### macOS (MacBook с Apple Silicon или Intel) — рекомендуемый способ

Откройте приложение «Терминал». Установите [Homebrew](https://brew.sh/), если его ещё нет; проверьте командой `brew --version`. После этого выполните:

```bash
# 1. Установить minimap2 из официального Homebrew
brew install minimap2

# 2. Установить официальный бинарный NCBI Datasets CLI для macOS
mkdir -p "$HOME/bin"
curl -fL --retry 3 \
  "https://ftp.ncbi.nlm.nih.gov/pub/datasets/command-line/v2/mac/datasets" \
  -o "$HOME/bin/datasets"
chmod +x "$HOME/bin/datasets"

# 3. Сделать datasets доступным из текущего терминала
export PATH="$HOME/bin:$PATH"

# 4. Проверить установку
datasets version
minimap2 --version
```

**Зачем `~/bin`?** EvoGene ищет `datasets` в этой папке даже тогда, когда её нет в переменной `PATH`. Чтобы команда `datasets` работала и в **новом** окне терминала (zsh), можно добавить путь в настройки оболочки:

```bash
touch "$HOME/.zshrc"
grep -qxF 'export PATH="$HOME/bin:$PATH"' "$HOME/.zshrc" || \
  echo 'export PATH="$HOME/bin:$PATH"' >> "$HOME/.zshrc"
source "$HOME/.zshrc"
```

Проверьте местонахождение исполняемых файлов и их доступность **из самого Python-проекта**:

```bash
command -v datasets
command -v minimap2

cd evogene  # если вы ещё не в каталоге проекта
python3 -c "from evogene.tools import check_tools; print(check_tools())"
```

Для обоих инструментов в результате `check_tools()` должно быть `'ok': True`. Путь к репозиторию может отличаться; команда `cd evogene` выполняется из его родительской папки, а если вы уже в проекте — пропустите её.

### Если установлен Conda / Miniforge

Альтернативный официальный способ — установить оба инструмента из `conda-forge` **в то окружение Conda, из которого будете запускать EvoGene**:

```bash
conda install -c conda-forge ncbi-datasets-cli minimap2
datasets version
minimap2 --version
```

При использовании `venv` вместо Conda предпочтителен способ macOS выше: бинарные программы не зависят от Python-виртуального окружения.

### Для более надёжной филогенетики (необязательно)

```bash
brew install mafft iqtree
mafft --version
iqtree2 --version  # в некоторых версиях команда называется iqtree
```

При наличии **MAFFT + IQ-TREE 2** EvoGene пытается построить ML-дерево с поддержкой ветвей. Если они отсутствуют, программа может показать **только предварительную NJ-кластеризацию по 7-мерам без поддержки**, что не является подтверждённой филогенией гена.

### Если EvoGene всё ещё пишет «не найден»

1. Завершите текущий Streamlit-процесс сочетанием **Ctrl+C** и запустите снова: `python -m streamlit run auto_app.py`.
2. Убедитесь, что обе команды `datasets version` и `minimap2 --version` работают **в том терминале, из которого запускается Streamlit**.
3. Выполните `python3 -c "from evogene.tools import check_tools; print(check_tools())"`. В нём виден реальный путь к найденному бинарному файлу или причина ошибки.
4. Если `brew` не находится, проверьте, установлен ли Homebrew, и настройте `PATH` по инструкции `brew shellenv` для вашей архитектуры Mac.
5. `(.venv)` перед приглашением терминала означает, что виртуальное окружение, вероятно, уже активировано; повторный `source .venv/bin/activate` может быть не нужен.

Официальные инструкции: [NCBI Datasets — Download and Install](https://www.ncbi.nlm.nih.gov/datasets/docs/v2/command-line-start/) и [Homebrew minimap2](https://formulae.brew.sh/formula/minimap2).

## Сценарий исследования

1. **Загрузка.** Выберите FASTA с несколькими кандидатными генами. Программа принимает ДНК `A/C/G/T/N`, длина одной записи — **30–100 000 нт**. Идентификаторы записей должны быть уникальными.
2. **Выбор видов.** Укажите исходный вид, например *Drosophila melanogaster*, и сравнительные виды (близкие родственники и внешние группы).
3. **Настройки.** При необходимости загрузите FASTA-библиотеку транспозонов; включите автоматический расчёт дерева.
4. **Исследование.** Нажмите «Запустить исследование» и наблюдайте этапы загрузки геномов, картирования, анализа геномного окружения, ORF и филогенетики.
5. **Выводы.** Откройте вкладки «Дерево», «Гипотезы», «Геномные данные» и «Технические проверки». Сводная таблица гипотез показывает **число обнаруженных диагностических признаков и качественную степень уверенности**.
6. **Воспроизводимость.** Во вкладке «Журнал» скачайте JSONL и ZIP со сведениями о входных данных, событиях, версиях сборок и вычисленных деревьях.

Пример **условного** входного файла (не последовательность реального гена):

```fasta
>candidate_A
ATGAAACCCGGGTTTAAACCCGGGTTTTAA
>candidate_B
ATGAAAGGCTTCCCGGGAAACCCGGGTTAA
```

Для исследования реальных генов следует загружать действительные последовательности CDS/геномных участков, согласованные с выбранным исходным видом. Для гена с интронами обычный геномный FASTA и сплайсированная CDS — **разные входные объекты**; возможные ORF в геномной ДНК не равны подтверждённой трансляции.

## Выходные файлы

После анализа результаты записываются отдельно для каждого запуска:

```text
results/evolutionary_pipeline/<run_id>/
├── candidate_genes.fasta
├── run_report.json
├── audit.jsonl
├── FBgn.../
│   ├── evidence.json
│   ├── gene_tree.nwk          # при достаточных данных
│   └── locus_alignment.fna   # если построено MSA
└── ...
```

В ZIP пользователь дополнительно получает `run_report.json`, `audit.jsonl`, загруженный FASTA (если доступен), Newick и MSA. Для воспроизводимости фиксируются исходные виды, версии сборок, параметры, время проверок и результаты завершения внешних программ.

## Другие режимы

```bash
# Расширенные ручные входы: локальные геномы/GFF3,
# кандидатные гены и сравнительные FASTA, данные статьи
python -m streamlit run app.py

# Пакетный анализ кандидатных генов из исходных геномов через CLI
python -m evogene.workflow_cli --help

# Пакетный анализ опубликованных Cactus/Spaln/Genewise-фрагментов
python -m evogene.case_batch_cli --help

# Полный набор Python-тестов
python -m unittest discover -s tests -v
```

Режим `app.py` поддерживает три самостоятельных сценария: (1) локальные сборки FASTA + GFF3; (2) прямые FASTA кандидатов и сравнительных последовательностей; (3) загруженный файл статьи Peng & Zhao с секциями Cactus, Spaln, Genewise.

Для обычных сравнительных FASTA используются заголовки:
- кандидаты: `>GENE_ID|FOCAL_SPECIES`;
- сравнения: `>GENE_ID|SPECIES|OPTIONAL_LOCUS`.

Эти предварительно отобранные данные не заменяют полный полногеномный поиск альтернативных гомологов.

### Работа с дополнительными данными статьи

Файл `supplementary_file_unannotated_alignments.fasta` (~53,9 МБ) **не является одним готовым множественным выравниванием**. В нём три секции:

| Секция | Назначение |
|---|---|
| Raw / Progressive Cactus | Извлечённые гомологичные геномные участки |
| Spaln | Предсказания сплайсированных последовательностей |
| Genewise | Независимые предсказания кодирующих соответствий |

В исходном файле — **780 идентификаторов генов**, 17 011 последовательностных записей в каждой секции (всего 51 033), коды **20 видов**. Отметки `score` и `shift_Yes/No` — метаданные программ, **не статистические вероятности** и не доказанные эволюционные события. Файл не следует загружать как обычный MSA или как последовательность одного гена.

Пример командного анализа:

```bash
python -m evogene.case_batch_cli \
  --input supplementary_file_unannotated_alignments.fasta \
  --gene FBgn0040343 \
  --gene FBgn0262810 \
  --gene FBgn0025616 \
  --method raw \
  --output results/case2_multi_gene.json
```

## Доказательства и ограничения

EvoGene разделяет **наблюдение** (совпадение ДНК, перекрытие CDS, координаты, потенциальная ORF, ветвь вычисленного дерева) и **гипотезу** (дупликация, de novo, перемещение и др.). Результат `insufficient_data` — полноценный научно корректный исход при нехватке данных.

В отличие от полного анализа Peng & Zhao, автоматический конвейер **пока не выполняет** в полном объёме Progressive Cactus/HAL, откалиброванную оценку Genewise/Spaln, глобальный поиск дальних гомологов UniProt/jackhmmer/TBLASTN, строгую реконструкцию предкового кодирующего состояния и экспериментальную проверку белковой трансляции. TE-поиск с пользовательской библиотекой не заменяет RepeatMasker/Dfam. Для доказательной эволюционной классификации необходимы внешние проверки и контрольные данные.

**Тесты репозитория** проверяют поведение кода и интерфейса, но не подтверждают биологическую точность классификации. Не используйте демонстрационные синтетические данные как независимую научную валидацию.

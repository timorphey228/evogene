# EvoGene v5 — наблюдаемый конвейер анализа генов

## Что делает приложение

1. Проверяет входной FASTA: целевой вид, длину и формат генной ДНК.
2. Скачивает сборки NCBI и доступные аннотации GFF3 для выбранных родственников.
3. Картирует последовательность minimap2 на каждый геном; сохраняет **все** попадания, а также количество качественных (покрытие >= 50%, приблизительная идентичность >= 65%). Отсутствие попадания не доказывает отсутствие гена.
4. Пересекает координаты попаданий с объединёнными интервалами CDS, учитывает доступность GFF3.
5. Скачивает референс исходного вида, картирует исследуемый ген на собственный геном **один раз** и ищет дополнительные неперекрывающиеся локусы (кандидаты на паралоги). Для неизвестного локуса оставляет синтению неопределённой.
6. Из GFF3 определяет число CDS-фрагментов исследуемого локуса и возможных гомологов (учитывая альтернативные транскрипты).
7. Из GFF3 извлекает идентификаторы **аннотированных белков исследуемого гена**, ищет их в белковом FASTA NCBI. Только если аннотированные белки недоступны, применяет шестира́мочный перевод геномной ДНК. Это принципиально для генов с интронами.
8. Делает предварительный белковый поиск: общие тетрапептиды, затем локальное выравнивание Biopython лучших кандидатов. Программа не выполняет BLASTP/DIAMOND, поэтому отрицательный результат чувствительность не гарантирует.
9. Картирует левый и правый фланги на родственников для приближённой синтении. Только подтверждённая синтения плюс отсутствие CDS-аннотации у гомологичной ДНК позволяет получить слабый сигнал de novo; без реконструкции предковой ORF — не доказательство.
10. Считает независимые свидетельства для de novo, ДНК-дупликации, ретропозиции, релокации/транспозиции и слияния генов. Выдаёт **candidate**, **partial_signal**, **no_signal** или **not_assessed**. Все механизмы могут быть совместимы с частью находок; они не суммируются в 100%.
11. Показывает этапы по каждому родственнику в реальном времени. Результат содержит `pipeline_events`, `protein_evidence`, `retrocopy_evidence`, `synteny_evidence`, `mechanism_report` и технические ошибки.

## Объективность и ограничения

**Нет ручной таблицы ожидаемых генов и нет механизма по имени гена.** Нельзя обещать, что Zeus будет распознан как ретроген, пока программа не нашла независимые свидетельства. Классификатор сейчас — исследовательский скрининг, а не подтверждённое эволюционное происхождение.

Класс de novo особенно сложен: отсутствие совпадения или CDS — не доказательство. Для валидированного вывода нужны соответствующие ортологичные синтенные интервалы, реконструкция предковых ORF, чувствительный поиск гомологов и филогенетический контекст.

Ретропозиция также требует проверки родителя, структуры интронов/экзонов, направления копирования и филогении. Геномное ДНК-выравнивание особенно плохо обнаруживает родителя, если он содержит интроны; переход к аннотированному белку повышает чувствительность именно этой проверки.

## Тестирование

```bash
python -m unittest discover -s tests -v
```

Синтетические unit-тесты проверяют корректность кода и независимость от ID, но не чувствительность/специфичность на реальных генах. Следующий научный шаг — отложенный датасет с опубликованными de novo, ретрогенами, дупликациями, отрицательными примерами и измеримыми false positives/false negatives.

# Как использовать supplementary_file_unannotated_alignments.fasta

## 1. Это не обычный выровненный FASTA

По проверенному загруженному файлу (53,868,412 байт) обнаружены:

| Раздел | Метод/источник | Генов | FASTA-записей |
|---|---|---:|---:|
| I | Raw hits из Progressive Cactus | 780 | 17,011 |
| II | Spliced align by Spaln | 780 | 17,011 |
| III | Spliced align by Genewise | 780 | 17,011 |
| **Итого** | 3 результата на набор генов | **780 разных ID** | **51,033** |

В файле встречается 20 видовых обозначений:
`dmel, dsim, dsec, dyak, dere, dfic, drho, dele, deug, dtak,
dbia, dkik, dana, dper, dpse, dmir, dwil, sleb, blat, bdor`.

Важное ограничение: 780 ID **не равны** 555 итоговым кандидатам de novo
из основной публикации. Это файл выбранных авторами хитов и предсказаний;
его нельзя интерпретировать как полный каталог всех проверенных генов
или как независимое подтверждение происхождения.

Нельзя подавать весь файл в MAFFT или IQ-TREE напрямую: строки
`Section I ...`, `raw sequence for ...`, `spaln for ...`,
`genewise for ...` не входят в стандартный синтаксис FASTA.
Кроме того, предсказания разных методов отличаются по длине, а часть
сырых записей — длинные геномные фрагменты. Это НЕ готовое MSA.

## 2. Открыть в EvoGene

```bash
git pull origin main
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

1. Выберите режим **«Данные статьи Peng & Zhao: Cactus / Spaln / Genewise»**.
2. Загрузите оригинальный `.fasta` (~54 МБ).
3. Интерфейс обнаружит все 780 ID генов и список 20 кодов видов.
4. Выберите один ген (например, `FBgn0040343`).
5. Выберите секцию **Raw**, **Spaln** или **Genewise**.
6. Выберите сравниваемые виды; в этом режиме доступны все 20.
7. Нажмите **«Исследовать выбранный ген»**.
8. Оцените таблицу совпадений и диаграммы, затем сравните
   число записей, длину и `shift` между тремя методами.
9. Скачайте JSON или выбранные **НЕ выровненные** последовательности
   в стандартном FASTA для следующих специализированных инструментов.

## 3. Что показывают данные и что не показывают

- **Raw**: потенциальные гомологичные участки ДНК, выбранные через
  полногеномное Cactus-выравнивание; не доказывают, что участок кодировал белок.
- **Spaln**: модель возможного сплайсированного гомолога, полученная
  по исходному кандидату; не доказывает трансляцию.
- **Genewise**: альтернативная модель возможного кодирующего гомолога,
  которую следует сопоставить со Spaln.
- **Headers**: `score_...` и `shift_...` сохранены *буквально*.
  Без обращения к коду исследования нельзя трактовать значение
  `score_1E10` как статистическую вероятность или называть
  `shift_Yes` доказанным эволюционным frameshift.
- **Local similarity**: процент идентичности рассчитан для локально
  выровненных позиций; широкие участки пропусков должны интерпретироваться
  отдельно. Слишком дорогие сравнения отображаются как
  `skipped_quadratic_cost`, а не как нулевые совпадения.
- **Coordinates**: название с геномными координатами — кандидатный
  соответствующий локус, но не доказательство некодирующего предка.
- **Unobserved species**: отсутствие записи у вида в таком выбранном
  исследовательском файле не доказывает отсутствие гена в геноме.

## 4. Как построить обоснованную филогению

Сначала разделите *дерево видов* и *дерево генного семейства*.

**Дерево видов** строится по независимым консервативным ортологам
или берётся из проверенной филогенетической публикации. Оно показывает
порядок разделения родственных линий; не должно выводиться из одного
краткого de novo белка.

**Дерево генов** строится только при доказанной гомологии кодирующих
последовательностей, после отбраковки ошибочных транскриптов и
разделения паралогичных копий. На кончиках дерева должны быть
`species|gene|copy`, а не только обозначения видов.

Рекомендуемый рабочий процесс:

1. Подтвердить гомологи белка BLASTp/DIAMOND/HMMER/TBLASTN
   и проверить синтенный контекст.
2. Экспортировать **подтверждённые белковые** или корректно
   сплайсированные кодирующие последовательности, не сырую
   геномную ДНК со случайными ORF.
3. Построить MSA MAFFT/MUSCLE, проверить информативность
   и неоднозначно выровненные участки.
4. Реконструировать дерево по ML, например IQ-TREE 2
   с выбором модели и проверкой UFBoot/SH-aLRT.
5. Укоренить по подходящей внешней группе, сравнить дерево
   генов с деревом видов и определить возможные дупликации/потери.
6. Повторить анализ на альтернативном MSA, наборе видов и модели.
7. Показать в EvoGene **настоящее** `.treefile` / Newick.
   Программа сейчас только отображает дерево, не создаёт его.
8. Если гомология сомнительна или ген слишком короткий,
   **не строить принудительно дерево**, а сопоставлять синтенные
   предковые участки и состояние ORF на дереве видов.

Пример команды для **уже проверенного белкового** выравнивания
(не для исходного `supplementary_file...`):

```bash
mafft --auto verified_protein_homologs.faa > verified_protein_homologs_aligned.faa
iqtree2 -s verified_protein_homologs_aligned.faa -m MFP -B 1000 --alrt 1000 -T AUTO
```

Файлы `.treefile`, `.iqtree` и выравнивание необходимо сохранять
вместе с версиями программ и исходными идентификаторами.
